HOI-Retarget:
Contact-Centric Retargeting for Human-Object Interaction

Contacts anchored to the object, not to the human motion — so they survive the embodiment gap, and adapt when the object does.

Jihwan Shin · Adrià López Escoriza · Junzhe He · Matthias Heyrman · Marco Hutter

Robotic Systems Lab, ETH Zürich

Paper arXiv Code Dataset 3D viewer Results

Abstract

Learning from demonstration (LfD) has enabled humanoid robots to acquire diverse whole-body skills, but extending this paradigm to human-object interaction (HOI) is limited by the availability of robot-compatible interaction references. We present HOI-Retarget, a contact-centric retargeting method that transfers HOI onto a humanoid robot for large-scale motion-data generation. Its windowed trajectory optimization uses every labeled contact as a target in the object frame, balancing body tracking, foot support and smoothness under the robot's kinematic limits. The method can augment a single demonstration across object sizes, absorb contacts reconstructed from monocular video, and extend to several robots manipulating one object. We publicly release the code and the retargeted motion dataset.

Method

How it works

Body pose alone is not enough. Because humans and humanoids differ in proportions, joint structure and reachable workspace, matching their poses independently can move a hand away from the object or shift it to a functionally different surface. HOI-Retarget instead optimizes directly against the contact the human made.

Contacts as object-frame targets

Every labeled contact is expressed as a target in the object frame rather than in the world. The optimization drives the robot's palm to that point, so the grasp lands on the surface the human actually used — and it re-anchors automatically when the object is rescaled.

Overlapping-window optimization

Body tracking, contact alignment, foot support and smoothness are balanced under the robot's joint-position and velocity limits. Overlapping windows couple consecutive frames, so jerk can be penalized and a contact resolved over its whole interval, while each program stays the same size however long the clip.

Correcting noisy contacts

Contact annotations recovered from monocular video are frequently wrong. An optional interactive tool lets the target location and time interval of each contact segment be corrected before the optimization runs.

Generality

Beyond a single dataset

To assess broader applicability, we retarget additional HOI datasets to both the Unitree G1 and H2; four of them join OMOMO in the released corpus. The same formulation also handles two-person demonstrations: each actor is retargeted against the shared object trajectory, producing synchronized multi-agent references. This establishes coverage at the kinematic level — mutual collision avoidance and dynamically coupled multi-robot execution are outside its scope.

Comparison

Against OmniRetarget

Interaction-aware retargeting preserves the overall body-object geometry, but does not minimize the error to each individual source contact. On objects with thin or spatially localized grasp regions the hand ends up somewhere the human never touched. GMR is an object-agnostic control: it tracks the human body while leaving the object interaction unconstrained, so it indicates the body-motion fidelity attainable when contact preservation is not optimized. Because neither baseline resizes the object mesh, mesh scaling is disabled here — all methods manipulate the same object geometry, and the object trajectory is adjusted only to bring it into the robot's workspace.

Data generation

Object-scale augmentation

One captured motion becomes many. Because the contact targets live in the object frame, resizing the object carries them with its surface, so the same clip can be re-solved at any object size without re-annotating the interaction. Sweeping the multiplier from ×0.25 to ×1.50 keeps the contacts on their labeled surface regions rather than leaving them at their original world positions. This shows geometric contact consistency over the tested range; it does not by itself establish dynamic feasibility at every generated size.

In the wild

From monocular video

To test a source outside a motion-capture setup, a subject is recorded with a monocular camera while moving a table contained in none of the datasets above, and CARI4D reconstructs the human mesh, the object mesh and their trajectories. Occlusion and depth ambiguity make the estimated hand contact alternate between penetration and separation, which would carry over after retargeting. We therefore collapse each sticking-contact segment to one point and manually correct the remaining displaced target before applying the same retargeting formulation. This establishes compatibility with a monocular reconstruction pipeline; it does not evaluate reconstruction accuracy across a video dataset.

Downstream

Dynamic refinement

A kinematic retarget is not yet physically feasible, and the pipelines that consume it differ in how they repair that. We apply two refiners of different families to references from OmniRetarget and from HOI-Retarget: a per-clip PPO policy trained in Isaac Lab with DeepMimic-style body- and object-tracking rewards, and the MuJoCo-based SBTO method of DynaRetarget. The RL tracker uses privileged observations and no domain randomization, so it generates physically consistent simulation trajectories rather than a deployable controller. Each reference type gets the same training or optimization budget. Under RL refinement our references cut object-path error from 0.285 to 0.213 m and the contact-point gap from 9.6 to 8.6 cm; under SBTO, from 0.269 to 0.194 m and 14.1 to 9.9 cm.

Release

Dataset

We publicly release the code and the retargeted motion dataset: kinematic humanoid interaction references drawn from five source datasets, with retargets for two humanoid platforms and synchronized multi-robot collaboration motions.

6,952robot HOI clips
13.8 hof retargeted motion
75unique objects
2humanoid platforms

The corpus is published as a Hugging Face dataset. Each row is one (motion, robot) pair: joint angles, a floating base, the 6-DoF pose of the object, and the per-link contact flags saying which palms and feet touch it at each frame. Every row also carries a low-resolution render of that exact trajectory, so the dataset viewer plays each clip inline.
